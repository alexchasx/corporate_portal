# Требования к корпоративному веб-порталу производственного предприятия

## 1. Общие сведения

- **Назначение:** единая точка доступа сотрудников к корпоративным сервисам, документам, коммуникациям и бизнес-процессам.
- **Масштаб:** от 10 000 активных пользователей; пиковая нагрузка — до 3 000 одновременных сессий.
- **Тип развёртывания:** on-premise или приватное облако; поддерживает горизонтальное масштабирование.
- **Доступ:** из корпоративной сети (LAN) и извне через VPN/мTLS.

## 2. Технологический стек

|------|-----------|--------|
| Backend | Laravel | 13 |

## 3. Архитектурные требования

- **Backend:** модульный монолит Laravel с чётким разделением на домены (HR, Документооборот, Новости, Опросы, Справочники). Структура модулей — по принципу Bounded Context.
- **Frontend:** Nuxt.js в режиме SSR для контентных страниц и SPA-режиме для интерактивных модулей. Включён Nitro-сервер, рендеринг настраивается per-route.
- **API:** RESTful-эндпоинты под мобильные/внешние клиенты; OpenAPI-спецификация генерируется из кода (Scribe или Scramble).
- **События:** асинхронная обработка через очереди Laravel (Redis-драйвер) — рассылки, тяжёлые импорты, генерация отчётов.
- **Реальное время:** WebSocket-сервер (Laravel Reverb / Soketi) для уведомлений и чата.
- **Сессии:** хранение в Redis; stateless-режим для API-токенов (Sanctum).

## 4. Функциональные модули

### 4.1. Аутентификация и авторизация
- Интеграция с LDAP/Active Directory (через ldaprecord-laravel).
- Поддержка SSO (SAML 2.0 / OAuth 2.0).
- Двухфакторная аутентификация (TOTP).
- Ролевая модель RBAC + ABAC для контекстных ограничений.
- Управление сессиями: список активных сессий, принудительный logout.

### 4.2. Личный кабинет сотрудника
- Профиль, контакты, фото, подразделение, должность — синхронизация с LDAP.
- Управление подписками на уведомления (каналы: email, SMS, push, in-app).
- Дашборд с виджетами: заявки, поручения, новости, опросы, дни рождения.

### 4.3. Структура предприятия
- Иерархия подразделений (дерево), справочник должностей.
- Управление сотрудниками: фильтры по подразделению, должности, статусу.
- Экспорт/импорт оргструктуры (XLSX, CSV).

### 4.4. Новостной портал
- Ленты: корпоративная, по подразделениям, теговая.
- Редактор контента (rich text + медиавложения).
- Модерация, публикация по расписанию, пины, архив.
- Комментарии с модерацией и анти-флудом.

### 4.5. Документооборот (упрощённый)
- Библиотека документов с категориями и версионированием.
- Предпросмотр PDF/DOCX/PPTX в браузере.
- Подписи: интеграция с внешней СЭД или простая электронная подпись.
- Жизненный цикл: черновик → согласование → опубликован → архив.

### 4.6. Задачи и поручения
- Создание задач с дедлайнами, приоритетом, ответственными.
- Канбан-доска, список, диаграмма Ганта (минимальная).
- Уведомления о приближении дедлайна.

### 4.7. Опросы и голосования
- Конструктор опросов: один/несколько вариантов, шкала, открытый ответ.
- Анонимные/именные опросы, квоты по подразделениям.
- Визуализация результатов в реальном времени.

### 4.8. Справочники
- Телефонный справочник с расширенным поиском.
- Нормативная документация, регламенты, инструкции.
- Управление справочниками администратором без разработки.

### 4.9. Поиск
- Глобальный поиск по сотрудникам, документам, новостям, задачам.
- Фасетный фильтр по типам контента.
- Подсветка совпадений, релевантная сортировка.

### 4.10. Администрирование
- Управление пользователями, ролями, правами.
- Аудит-журнал действий (action log).
- Управление конфигурацией портала: темы, логотип, баннеры.
- Мониторинг очередей, сессий, производительности.

## 5. Нефункциональные требования

### 5.1. Производительность
- Время ответа API — не более 300 мс (P95) при штатной нагрузке.
- Время первой отрисовки страницы (FCP) — не более 1,5 с.
- Lighthouse-метрики: Performance ≥ 85, Accessibility ≥ 90.
- Кэширование: HTTP-кэш (Nginx), Redis-кэш запросов, кэш на уровне Nuxt (useFetch + payload).

### 5.2. Масштабируемость
- Backend: stateless-инстансы за load balancer, горизонтальное масштабирование.
- БД: репликация read-replica, партиционирование крупных таблиц (аудит, логи, документы).
- Файловое хранилище: S3-совместимое (MinIO) для вложений и медиа.
- Очереди: раздельные connection для разных очередей, автоскейлинг воркеров.

### 5.3. Безопасность
- Шифрование TLS 1.3, HSTS, CSP-заголовки.
- Защита от OWASP Top 10: CSRF-токены, XSS-санитизация, parameterized queries (Eloquent).
- Rate limiting на API и формы аутентификации.
- Секреты: хранение в Vault или в env-переменных контейнера, не в репозитории.
- Бэкапы БД: ежедневные инкрементальные, еженедельные полные, хранение 30 дней.
- Маскирование персональных данных в логах (Laravel PII-redaction).

### 5.4. Адаптивность и кросс-платформенность
- Вёрстка по методологии mobile-first.
- Поддержка разрешений: 360px — 4K.
- Тестирование в Chrome, Firefox, Safari, Edge; iOS 15+, Android 10+.
- Брейкпоинты Vuetify 3 без переопределения базовой сетки.
- Доступность: WCAG 2.1 AA — семантическая разметка, aria-атрибуты, контраст, навигация с клавиатуры.

### 5.5. Локализация
- Мультиязычность через vue-i18n (Nuxt module) и Laravel Translatable.
- Минимум: русский + английский; архитектура поддерживает добавление языков без рефакторинга.

### 5.6. Надёжность
- Graceful degradation: при недоступности поиска/уведомлений основной функционал продолжает работать.
- Health-check эндпоинты для всех зависимостей (БД, Redis, S3, LDAP).
- SLA: доступность 99,5%; плановые работы — в часы минимальной нагрузки.

## 6. Интеграции

| Система | Протокол | Назначение |
|---------|----------|------------|
| LDAP / AD | LDAP | Синхронизация пользователей, SSO |
| Внешняя СЭД | REST/SOAP | Документооборот, маршруты согласования |
| ERP (1C / SAP) | REST/OData | Оргструктура, табель, зарплатные проекты |
| Почтовый сервер | SMTP/IMAP | Уведомления, импорт писем |
| Push-сервис | FCM/APNs | Мобильные push-уведомления |
| Системы мониторинга | Prometheus/Grafana | Метрики, алерты |

## 7. Разработка и поставка

- Git-флоу: `main` (production), `staging`, feature-ветки.
- CI/CD: автоматический линтинг (PHP CS Fixer, ESLint, Prettier), статический анализ (PHPStan level 8), тесты, сборка Docker-образа, деплой на staging при merge.
- Тесты: PHPUnit (unit + feature ≥ 70% coverage), Vitest (компоненты Vue), Playwright (E2E — критические пути).
- Code review: обязательный, минимум один аппрув.
- Миграции БД: только через Laravel migrations, reverse-миграции для всех destructive-изменений.
- Код-стайл: PSR-12 (PHP), официальные гайды Vue.js Style Guide.

## 8. Структура репозиториев

- **backend/** — Laravel-приложение, API, миграции, доменные модули.
- **frontend/** — Nuxt.js-приложение, компоненты Vuetify, плагины, middleware.
- **docker/** — Dockerfile, docker-compose, entrypoint-скрипты.
- **docs/** — архитектурные документы, OpenAPI-спецификация, runbook.
- **deploy/** — Helm-чарты или Ansible-плейбуки.
- **.gitlab-ci.yml / .github/** — пайплайны CI/CD.

## 9. Критерии приёмки

- Развёртывание из одного docker-compose-файла в режиме `docker compose up`.
- Все E2E-тесты проходят в свежем окружении.
- Нагрузочный тест: 3 000 одновременных пользователей, P95 < 500 мс.
- Аудит безопасности без критических уязвимостей.
- Lighthouse-аудит всех ключевых страниц соответствует метрикам из раздела 5.1.
- Документация: README с инструкцией запуска, OpenAPI-спецификация, схема БД.
